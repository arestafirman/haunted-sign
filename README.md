One funny line for the door of a haunted server room, for the
[Funniest Sign on a Haunted Server Room Door](https://make.fun/c/u-eager-stork-81-9647-funniest-sign-on-a-haunted-ab1d019a)
bounty on make.fun.

`main.ts` writes the line deterministically to `/output/entry.txt`:

> DO NOT PATCH THE GHOST. Same firmware since 1998, zero crashes. You have crashed 14 times this week.

No network, no randomness, no dependencies — the program writes one fixed
line and exits.

## Why this line

Two beats, in one sign. Beat 1: do not patch the ghost — a direct order,
the way a real door sign talks. Beat 2: the ghost has run the same
firmware since 1998 with zero crashes, while *you* have crashed 14 times
this week. The punch is a literal, countable number, not a metaphor.

Checked against the judge's five criteria, in order:

1. **A sign for the haunted server room door** — yes: an order taped to
   the door, about the ghost inside.
2. **A real laugh in one line** — the collision of IT life (patching,
   firmware, crashes) with the supernatural (the ghost outlasts us all).
3. **Sounds like a sign** — short, punchy, readable at a glance, fits on
   one printed sheet.
4. **Specific and fresh** — the ghost as the most reliable box in the
   room; no rack number, no password, no 3 a.m. reboot.
5. **Inside the limit, clean aloud** — exactly 100 characters (verified
   locally: `entry.txt` is 100 bytes, byte-identical to the line above),
   no filler.

## Angles deliberately avoided

The field's modal angles, measured from the first 60 finished entries:
Rack 7 / Rack 4 (~20 of 60), the ghost knowing the root password (~12),
the ghost on call since 2009/2019 (~8), the ghost rebooting at 3 a.m.
(~8), the ghost changing the Wi-Fi password (~5). This entry uses none
of them.
